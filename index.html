swiiifz

sw · iiif · z = Service Worker · IIIF · Zipped (pronounced “swiff-zee”)
IIIF from a single zip file, served by a Service Worker

A whole IIIF tree (a Presentation 3 manifest plus level 0 tiles for every page) lives in one stored zip file on a static host. A Service Worker (lib/swiiifz-sw.js, mounted with lib/swiiifz.js) answers the viewer's requests for manifest.json, info.json and tiles by reading the zip's central directory once, then fetching each entry with an HTTP Range request. No server code, no unpacking, no build step on the host.

The document is ARCHIVI & COMPUTER, anno V, fascicolo 1/1995 (source PDF), converted with mkiiif. The same manifest opens in different viewers, to check that each one works through the Service Worker:

  • triiiceratops 1.2.0
  • Mirador 4.3.0
  • Universal Viewer 4.4.4
  • TIFY 0.36.2
  • Clover IIIF 3.17.0
  • Leaflet-IIIF 3.0.0 · Image API only, one page at a time

Open DevTools → Network to watch it: each tile appears as a virtual request answered by the Service Worker, plus a 206 Partial Content request for its bytes in the zip.
